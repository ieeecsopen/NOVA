# NOVA — Language Constitution

Phase 1 output. **This document is not [CONSTITUTION.md](../../CONSTITUTION.md).**
That document governs *process* — how NOVA decides what to add, in what
order, and who breaks ties (the RFC process, the priority order, the
feature bar). This document states NOVA's *semantic* commitments — what
must be true of the language itself, independent of how any particular
feature gets there. Read together: CONSTITUTION.md is how NOVA decides;
this is what NOVA has decided.

Every principle below uses the vocabulary defined in
[LANGUAGE-PHILOSOPHY.md](LANGUAGE-PHILOSOPHY.md) and is stated so it can
be checked against the current implementation, not just agreed with in
the abstract. Each carries a **status**: *met* (there is code and a
conformance test), *partially met*, *aspirational* (no code yet, gated by
a milestone), or *vacuous* (trivially true only because the feature it
would constrain doesn't exist yet).

---

## Principle 1 — Safe code must not permit undefined memory behavior

No well-typed NOVA program outside an explicit, capability-gated escape
hatch may exhibit use-after-free, data races on shared mutable state, or
any behavior the specification does not define.

**Status: aspirational, vacuously true today.** There is no memory model
(Milestone 1; Constitution Article XI). v0.1 has no pointers, no mutation
beyond `let`-shadowing, and no `unsafe`, so nothing in it *can* exhibit
undefined behavior — which is a fact about the language's current
poverty, not a guarantee anyone has earned. [RESEARCH.md §R1](../../RESEARCH.md#r1--memory-safety)
sets the bar this must eventually clear: RustBelt's machine-checked
soundness proof for Rust.

---

## Principle 2 — External effects require explicit authority

A computation may exercise a capability only if that capability is
reachable from its parameters or captures, and its declared effect row
must equal (not merely cover) what its body actually performs.

**Status: met.** This is RFC 0001 in full, checked by diagnostics E0201–
E0206, exercised by the conformance suite (25 tests) and stress-tested
by four adversarial attempts to launder authority past it (conformance
021–024), three of which were correctly rejected and one of which was
correctly accepted for a documented reason (capability *values* are made
visible by ordinary typing; only capability *uses* need the row). This is
the one principle on this list NOVA can point at working, tested code
for.

---

## Principle 3 — Failure must have explicit semantics

Whether an operation may fail, and what failing means (an exception, a
`Result`, a panic, a partial effect), must be part of its checked type,
not documented separately from it.

**Status: not met.** v0.1 has no user-visible failure mechanism —
`Interpreter` raises Python exceptions for runtime errors (division by
zero, missing host implementation), which is an implementation detail of
the reference semantics, not a NOVA-level construct. This is upstream of
[P10](../../PROBLEM-SPACE.md#p10--failure-semantics-are-untyped) (retry-safety):
a `with_retry` cannot refuse to retry a non-idempotent operation until
NOVA can say, in types, that an operation *can fail* at all. No RFC yet.

---

## Principle 4 — Concurrency must have well-defined safety guarantees

If NOVA has concurrency, data-race freedom must be a consequence of the
memory model (Principle 1), not a mechanism added beside it.

**Status: not met, vacuously true today** (no concurrency exists to
violate it). Recorded now specifically to foreclose the failure mode
[RESEARCH.md §R6](../../RESEARCH.md#r6--concurrency) found repeatedly: Java and
Go added concurrency before a race-freedom story and never fully
recovered; Rust, Pony, Verona, and Swift 6 got the guarantee only where
it was designed in from the memory model outward. Gated on Milestone 1
before Milestone 4 begins, in that order, permanently.

---

## Principle 5 — AI-generated code receives no special trust

No mechanism anywhere in the checker, the effect system, or the module
system may grant a weaker check, a wider default row, or an implicit
`widen` based on who or what authored a piece of code.

**Status: met, by construction, and worth stating anyway.** Nothing in
`verifier/refspec/check.py` has a notion of authorship — RFC 0001's
derivation rule is computed from a function's body alone. The principle
is recorded not because it is at risk today, but because it names the
*specific shortcut* that will be proposed eventually — a fast-path that
skips effect derivation for code marked "reviewed" or "generated by a
trusted model" — and forecloses it in advance. It is the concrete reason
[NON-GOALS.md §4.2](NON-GOALS.md#42-silent-effect-subsumption) and
[§4.4](NON-GOALS.md#44-a-no_effects--trust-me-attribute) exist: both are
mechanisms this principle would be violated by, arriving under a
provenance-based justification rather than an ergonomics-based one.

---

## Principle 6 — Claims about resources must distinguish estimates from guarantees

A stated bound on cost, time, or capability use must be labeled as one of:
an unchecked estimate, or a checked bound (per the Guarantee ladder,
[LANGUAGE-PHILOSOPHY.md entry 10](LANGUAGE-PHILOSOPHY.md#10-guarantee)).
A tool must never present the former as the latter.

**Status: partially met, and already tested in miniature.**
[Experiment 003](../experiments/003-graded-rows.md) built exactly this
distinction into the grading pass — an earlier version silently returned
`{}` (a false, precise zero bound) for a function whose real cost was
unknown, and the fix was to introduce a distinct `UNKNOWN` state rather
than let an absent bound masquerade as a proven one. That bug, and its
fix, is the smallest possible working demonstration of this principle.
The general resource system (Milestone 5) does not exist yet.

---

## Principle 7 — Verification strength must be explicit

Every checked property in NOVA's documentation and diagnostics must state
which rung of the Guarantee ladder it occupies: assumption, declared,
guarantee, or verified-guarantee.

**Status: partially met.** RFC 0001's diagnostics always report a
*checked* fact (level 3) and never overstate it. SECURITY.md already
practices this discipline in prose ("what NOVA does not guarantee,"
stated plainly). What's missing is a machine-checkable *verified*-level
(level 4) — Milestone 6, layered SMT verification, not yet designed —
and a consistent label in tooling output, not just in hand-written docs.

---

## Principle 8 — Portability must be semantic

A program compiled to two different targets must have the same checked
meaning on both — the same effect rows mean the same authority, the same
types mean the same values — not merely the same source text accepted by
two toolchains.

**Status: aspirational.** No code generator exists (Milestone 3). The bar
this sets is the WebAssembly Component Model's formal semantics for
component boundaries
([RESEARCH.md §R16](../../RESEARCH.md#r16--webassembly-wasi-and-the-component-model)),
which is established, industrially backed, and not NOVA's invention —
NOVA's commitment is to *target* it rather than a bespoke ABI, per thesis
T2 ([DESIGN-OPPORTUNITIES.md §4](../../DESIGN-OPPORTUNITIES.md#4-theme-c--boundaries-and-the-adoption-problem)).

---

## Principle 9 — Ordinary code should remain simple

A program that uses none of NOVA's advanced constructs must read as a
small, unremarkable language — comparable in surface complexity to Go
or a scripting language, not to a research paper.

**Status: met, in the small.** `examples/hello.nova` is three lines with
one visible authority parameter and no other ceremony. This is
Constitution Article III's ergonomics ranking made testable: a specific,
inspectable artifact, not a promise.

---

## Principle 10 — Advanced features must not contaminate simple programs unnecessarily

Adding a feature aimed at advanced use (generics, refinements, grading,
effect handlers) must not change the parse tree shape, the type-checking
cost, or the required ceremony of a program that uses none of it.

**Status: a standing engineering commitment, testable and not yet
tested**, because none of the advanced features exist yet to check it
against. Recorded here as a **regression-test obligation on every future
milestone**: when generics land (Milestone 2), a zero-generic program's
AST node count and check time must be unaffected; when refinements land
(Milestone 6), a zero-refinement program must pay nothing. This makes
Constitution Article VI question 6 ("what does it cost a reader who does
not use the feature") into a number someone has to produce, not a
sentence someone has to write.

---

## Two additional principles Phase 0 surfaced

The brief invited "at minimum" the ten above. Two more are load-bearing
enough, and specific enough to Phase 0's findings, to state as
principles rather than leave as prose in a research document.

### Principle 11 — Authority and information are governed by dual, not identical, mechanisms

A capability-safe program (Principle 2) is not thereby an information-
flow-safe program. NOVA must never claim, imply, or design as though
"no ambient authority" entails "no data leaks."

**Why this needs to be a principle, not just a fact.** "No ambient
authority" *sounds* like it should prevent a logging library from leaking
a password, and it does not — the library still holds a `Runtime` and is
fully entitled to call `print` on whatever string reaches it.
[DESIGN-OPPORTUNITIES.md §5](../../DESIGN-OPPORTUNITIES.md#5-theme-e--what-does-not-unify)
found these are dual concerns (one constrains what code may *do*, the
other what data may *reach*), and thirty years of information-flow-
control research
([RESEARCH.md §R14](../../RESEARCH.md#r14--information-flow-and-agent-security))
show the hard part — declassification — gets nothing from capabilities.
This principle exists so the conflation is never made by accident under
pressure to claim more security than the row provides. Restates
[SECURITY.md](../../SECURITY.md)'s disclaimer and
[NON-GOALS.md §4.1](NON-GOALS.md#41-information-flow-control-for-now)
as a binding design principle rather than a caveat.

**Status: met**, in the only sense currently possible — by NOVA claiming
nothing here that would violate it.

### Principle 12 — A checked claim must be cheaper to state than to fake

Wherever NOVA offers both a checked path and an escape hatch (`widen`,
future attenuation, future `unsafe`), writing the honest, checked version
must cost the programmer less effort than reaching for the escape hatch
out of impatience.

**Why this needs to be a principle.** Every effect system that allows
silent widening decays the same way: the honest annotation is more
friction than the escape hatch, so the escape hatch wins by default and
the row becomes decoration
([NON-GOALS.md §4.2](NON-GOALS.md#42-silent-effect-subsumption)). RFC
0001 §7 already names the empirical test — the `widen` rate on real
code — but a rate is a measurement, not a commitment. This principle is
the commitment the measurement is checking: if `widen` usage climbs
above the 10% ceiling RFC 0001 sets, the correct response is to make the
honest path *cheaper*, not to raise the ceiling.

**Status: aspirational** — untestable until a real NOVA codebase exists
to measure (VISION.md already lists this as a falsifier not yet run).

## What NOVA fundamentally is

A statically typed, capability-safe, effect-tracked language whose
central mechanism is one row — checked today for authority, designed to
be checked eventually for cost — attached to every function type and
derived from context rather than authored by hand; built toward a memory
model it does not yet have, targeting native code and WebAssembly
components it does not yet generate, on the thesis that
[non-functional obligations are one mechanism, not many](../../DESIGN-OPPORTUNITIES.md#8-five-candidate-theses-ranked).

## What NOVA is NOT

Everything [NON-GOALS.md](NON-GOALS.md) says, at length, with reasons.
In one line each: not a proof assistant, not a probabilistic language,
not an array/schedule DSL, not a web framework, not a blockchain, not
self-hosted yet, not competing on memory safety before Milestone 1 exists,
not claiming information-flow safety, not adding an escape hatch that
isn't `widen` or an audited attenuation, not adopting syntax for a
category (agent, uncertainty, execution strategy) before that category
has an operational semantics — and, as of this document, not describing
its own program model as ten independent peers when four of them are one
mechanism and two are open questions.
